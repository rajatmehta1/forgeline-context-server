What ForgeLine is, who it serves, and what problem it solves.

The Problem

AI coding tools like Cursor, Copilot, and Claude Code generate code without awareness of your team's security rules, architecture boundaries, or existing codebase patterns. This leads to repeated security vulnerabilities, phantom package hallucinations, and code that ignores your existing utilities — creating tech debt faster than humans can review it.

Without ForgeLine
  • AI writes SQL with string concatenation (SQL injection)
  • AI re-invents helpers that already exist in utils/
  • AI imports packages your team hasn't approved
  • AI ignores PII/PHI handling requirements
  • Controllers call database directly, bypassing services
  • No awareness of team naming conventions
With ForgeLine
  • Security rules injected before every generation
  • Existing functions surfaced — AI reuses, not reinvents
  • Package approval check before any new import
  • PII/PHI/PCI constraints embedded in context
  • Architecture layer boundaries enforced
  • Team conventions included in every prompt

What ForgeLine Does

🔒

Security Rule Injection

Injects OWASP-aligned rules (SQL injection, eval, input validation, secret management) per architecture layer before generation.

🏗️

Architecture Enforcement

Defines which layers can call which — controllers cannot bypass services to hit the DB directly.

♻️

Pattern Reuse

Surfaces existing functions and classes near the target file from the Neo4j knowledge graph. Prevents reinvention.

🔍

Dependency Vetting

Checks packages against an approved list and trust score. Catches phantom/hallucinated package names before they enter code.

🛡️

Data Sensitivity Rules

Classifies fields as PII, PHI, PCI, FINANCIAL, or CREDENTIAL and injects handling constraints (encryption, logging bans) into context.

📐

Coding Standards

Injects naming conventions, async patterns, and team style guide rules. Configurable per policy profile.

Who Uses This

👩‍💻

Application Developer

Writes code in Cursor or Claude Code. ForgeLine transparently enriches their AI interactions with governance context.

🏛️

Platform / Security Team

Defines policy profiles, approved packages, and architecture rules. ForgeLine enforces them automatically in every AI generation.

🔬

Engineering Manager

Gets assurance that AI-generated code follows team standards without requiring manual review of every AI suggestion.

Scope Boundaries

In Scope

  • MCP server exposing tools/resources/prompts
  • Neo4j-backed code knowledge graph queries
  • Built-in default policy rules (security, arch, style, testing, perf)
  • Custom policy loading from YAML files
  • Dependency trust scoring and phantom detection
  • Data sensitivity classification and constraint injection
  • IDE integration via stdio transport
  • Remote team deployment via HTTP transport
  • Docker Compose local development setup

Out of Scope

  • Blocking / intercepting AI completions at runtime
  • Code scanning or static analysis of generated output
  • Real-time CVE vulnerability database (planned)
  • UI/dashboard for policy management (planned)
  • Multi-tenant user authentication (planned)
  • PostgreSQL policy storage (config present, not yet wired)
  • Automatic codebase indexing into Neo4j
  • Language server protocol (LSP) integration
