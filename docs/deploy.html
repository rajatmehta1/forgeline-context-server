Deployment Guide
Local development, Docker, IDE integration, and team deployment.

Deployment Modes

Topology Options

Local Development Setup

1

Install dependencies with uv

uv is the recommended package manager. It creates a virtual environment automatically.

# Install uv if you don't have it
pip install uv

# Sync all dependencies (including dev extras)
uv sync

# Or with pip (alternative)
pip install -e ".[dev]"
2

Configure environment

Copy the example env file and fill in your database credentials.

cp .env.example .env
3

Start Neo4j (optional but recommended)

The server works without Neo4j (policy-only mode), but you lose pattern and sensitivity queries. Use Docker for the easiest setup.

# Start Neo4j and PostgreSQL via Docker Compose
docker compose up -d

# Seed the knowledge graph with sample data
python scripts/seed_kg.py
4

Run the server

# stdio mode (for IDE integration)
uv run python -m src.server

# HTTP mode (for remote access)
uv run python -m src.server --transport streamable-http --port 8000

# Debug with MCP Inspector UI (uses fastmcp CLI)
uv run fastmcp dev inspector src/server.py

Docker Compose

The included docker-compose.yml spins up Neo4j and PostgreSQL. The MCP server itself can also be containerized using the provided Dockerfile.

# Start all services
docker compose up -d

# View logs
docker compose logs -f forgeline

# Stop
docker compose down
Note: MCP stdio transport cannot run inside Docker for IDE integration — the IDE needs to spawn the process directly. Use Docker only for the HTTP transport mode or for the backing databases (Neo4j, PostgreSQL).

Transport Modes

stdio

Standard I/O

The IDE spawns the MCP server as a child process and communicates over stdin/stdout. Default mode. All logging must go to stderr (already configured) to avoid corrupting the MCP wire format.

TRANSPORT=stdio
streamable-http

HTTP / SSE

Server listens on a TCP port. IDEs connect over HTTP. Suitable for a shared team deployment. Multiple developers share one server instance and the same policy set.

TRANSPORT=streamable-http
SERVER_PORT=8000

Seeding the Knowledge Graph

The seed script (scripts/seed_kg.py) populates Neo4j with sample data representing a TypeScript SaaS codebase. It creates 12 modules, 11 functions, 6 classes, 5 sensitive data fields, 8 dependencies, and 3 architecture boundary rules.

# Ensure Neo4j is running, then:
python scripts/seed_kg.py

# Output:
# ✅ Neo4j seeded with sample data!
#    • 12 modules, 11 functions, 6 classes
#    • 5 sensitive data fields, 8 dependencies
#    • 3 architecture boundary rules
Warning: The seed script runs MATCH (n) DETACH DELETE n first — it wipes all existing Neo4j data before seeding. Use only on a development database.
