1. Pre-flight Checks

Before testing individual tools, confirm all services are up and the server can start cleanly.

# 1. Confirm Docker services are running
docker compose ps
# Expect: forgeline-mcp, neo4j — both "Up" and healthy

# 2. Confirm Neo4j is reachable
curl -s http://localhost:7474/db/data/ | head -5
# Expect: JSON response with Neo4j version info

# 3. Start the MCP server manually to check for errors
uv run python -m src.server
# Expect in stderr:
#   Connected to Neo4j  uri=bolt://localhost:7687
#   ForgeLine Context Server ready
⚠

If you see "Knowledge Graph unavailable — running with policies only", the server still starts but Neo4j is unreachable. Fix the connection before testing pattern/sensitivity tools. Check NEO4J_PASSWORD in your .env — the seed script uses forgeline-dev as the password.

3. MCP Inspector — Primary Testing Method

The MCP Inspector is a browser-based UI that lets you call every tool and read every resource interactively, with live JSON output. It's the fastest way to test the full surface of the server.

# Start the MCP Inspector (opens a browser tab automatically)
uv run mcp dev src/server.py

# Output will show something like:
#   MCP Inspector running at http://localhost:5173
#   Proxying to: python -m src.server
ℹ

The Inspector spawns the server as a subprocess (stdio mode) and gives you a UI to call each tool with custom arguments and see the exact text returned. No IDE setup needed.

Inspector UI Workflow

  1. Open http://localhost:5173 in your browser after running the command above
  2. The left panel shows Tools, Resources, and Prompts tabs — all populated from your server's MCP schema
  3. Click a tool name → fill in the argument fields → click Run Tool
  4. The right panel shows the raw text response — this is exactly what an AI coding tool would receive
  5. Check the Server Log tab to see structlog output from the server including Neo4j query calls

4. Testing All 6 Tools

For each tool below: the test inputs are based on the seeded acme-saas data. Use these exact values to get meaningful responses.

Tool 1

get_context_for_file

The primary tool. Tests that the full context assembly pipeline works end-to-end — layer inference, policy lookup, pattern query, sensitivity query, and architecture boundaries all in one call.

Test inputs to try

src/services/payment.service.ts src/controllers/auth.controller.ts src/repositories/user.repository.ts src/utils/encryption.ts src/unknown/newfile.ts (unknown layer)
Inspector / curl input
file_path: "src/services/payment.service.ts"
repo_name: "acme-saas"
profile_id: "default"
Expected response (truncated)
# ForgeLine Governance Context
**File:** `src/services/payment.service.ts`
**Layer:** service | **Language:** typescript
---

## Security Requirements
- NEVER build SQL queries with string concat...
- ALWAYS hash passwords with bcrypt...

## Existing Functions (REUSE these)
- `processPayment(userId, amount, token)` in src/services/payment.service.ts

## Data Sensitivity Rules
- `card_token` [PCI]: Never store after auth...
- `amount` [FINANCIAL]: Use Decimal not float...

What to verify

  • ✓ Response header shows correct Layer: service and Language: typescript
  • ✓ Security section lists at least 5 rules (SEC-001 through SEC-005)
  • ✓ "Existing Functions" section shows processPayment from the seeded data
  • ✓ Data Sensitivity section shows card_token [PCI] and amount [FINANCIAL]
  • ✓ Architecture section says service layer MUST NOT import from: controller
  • ✓ Server log (stderr) shows: Building context, Resolved layer, Context built
💡

Try with file_path: "src/unknown/newfile.ts" and no repo_name. You should still get security and style rules (from the policy engine) even though Neo4j has no record of this file — this confirms graceful fallback works.

## `passwordHash` [CREDENTIAL]

What to verify

7. HTTP Mode — curl Testing

Switch to HTTP transport to test via curl. This mode is also how the Docker-deployed server works.

# Start in HTTP mode
uv run python -m src.server --transport streamable-http --port 8000
# Or via env var:
TRANSPORT=streamable-http uv run python -m src.server

List available tools (MCP initialize)

curl -s -X POST http://localhost:8000/mcp \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}' | python -m json.tool
expected — 6 tools returned
{
"result": {
"tools": [
{ "name": "get_context_for_file", ... },
{ "name": "get_security_rules", ... },
{ "name": "get_existing_patterns", ... },
{ "name": "get_architecture_map", ... },
{ "name": "check_dependency", ... },
{ "name": "get_data_sensitivity", ... }
]
}
}

Call a tool via curl

curl -s -X POST http://localhost:8000/mcp \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "id": 2,
    "method": "tools/call",
    "params": {
      "name": "get_context_for_file",
      "arguments": {
        "file_path": "src/services/payment.service.ts",
        "repo_name": "acme-saas"
      }
    }
  }' | python -m json.tool

10. Troubleshooting

Tools return empty patterns

  • → Neo4j not seeded — run python scripts/seed_kg.py
  • → Wrong password in .env — seed uses forgeline-dev
  • → repo_name mismatch — seed data uses acme-saas
  • → File path doesn't match seed prefix — use src/ not absolute paths

Server fails to start

  • → Check uv sync ran successfully
  • → MCP stdio mode: ensure no print() calls in server (breaks protocol) — all output must be structlog to stderr
  • → Port 8000 in use (HTTP mode) — change SERVER_PORT
  • → Python version — requires 3.11+: python --version

IDE not calling tools

  • → Restart the IDE after changing MCP config
  • → Check the path in --directory is the absolute path to this repo
  • → Verify uv is on your PATH: which uv
  • → Check IDE MCP logs for subprocess errors

get_data_sensitivity returns nothing

  • → The Cypher query uses a UNION — both branches must work
  • → Check DataField nodes exist: MATCH (d:DataField) RETURN count(d)
  • → DataField's source_module must start with the directory prefix of the requested file path
  • → Confirm sensitivity_tag <> 'NONE' — seeded fields have PII/PCI/etc.

Enable debug logging

# See every Neo4j query and cache hit/miss
LOG_LEVEL=DEBUG uv run python -m src.server

# Or in your .env:
LOG_LEVEL=DEBUG

Manually test Neo4j connection from Python

from neo4j import AsyncGraphDatabase
import asyncio

async def test():
    driver = AsyncGraphDatabase.driver(
        "bolt://localhost:7687",
        auth=("neo4j", "forgeline-dev")
    )
    async with driver.session() as s:
        result = await s.run("MATCH (n) RETURN count(n) AS total")
        data = await result.single()
        print(f"Total nodes: {data['total']}")  # Should be 36
    await driver.close()

asyncio.run(test())
