Core Concepts
The key ideas and abstractions that make ForgeLine work.

1. Model Context Protocol (MCP)

Protocol

MCP is an open standard (by Anthropic) that lets AI coding assistants call external servers for structured context. ForgeLine implements an MCP server using FastMCP, exposing three kinds of capabilities:

Tools

Functions the AI can call to retrieve information on demand. The AI decides when to call a tool during a conversation. Tools return structured text that gets appended to the AI's context window.

Resources

Static or semi-static data documents the AI can read for reference. In ForgeLine these expose full policy lists, architecture graphs, and the style guide. Accessed via URI scheme forgeline://...

Prompts

Reusable prompt templates that encode best practices for invoking the server's tools. The code_with_governance prompt instructs the AI to call get_context_for_file and get_existing_patterns before generating any code.

2. The Code Knowledge Graph

Neo4j

ForgeLine stores a graph of your codebase in Neo4j. Each node represents a code entity, and edges represent relationships. This enables rich queries like "find all exported functions in the same module directory as this file".

Neo4j Graph Schema

Queries are written in Cypher and look up modules by file path prefix (directory-level scoping). All query results are cached with a TTL cache to avoid repeated Neo4j round trips.

3. The Policy Engine

In-Process

The policy engine lives entirely in Python — no database needed. It ships with a default set of rules covering six categories, and can load custom profiles from YAML files.

Rule Severity Levels

BLOCK

Must never be violated. Used for SQL injection, hardcoded secrets, plaintext passwords.

WARN

Should be followed. Used for layer boundary violations, N+1 queries, missing tests.

SUGGEST

Best practice guidance. Used for naming conventions, async patterns, code style.

Layer-Based Filtering

Rules are filtered by the architecture layer of the target file. For example, test layer files only get testing rules; repository layer files don't receive controller-oriented architecture warnings.

4. Architecture Layers

Layered Architecture

ForgeLine models codebases using a standard layered architecture. It infers which layer a file belongs to either from Neo4j (authoritative) or from path patterns as a fallback.

5. Data Sensitivity Classification

Compliance

ForgeLine classifies data fields by sensitivity type and injects handling requirements directly into the AI's context. Each classification has a fixed set of constraints.

PII

Personally Identifiable Information. Encrypt, never log, consent required.

PHI

Protected Health Info. AES-256, audit trail, BAA required for external transfer.

PCI

Payment Card Data. Never store after auth, tokenize, never log even partially.

FINANCIAL

Money amounts. Use Decimal not float, audit trail, validate before write.

CREDENTIAL

Passwords/tokens. bcrypt/argon2, never in API responses or logs.
